# Kavinda Weerasekara — UI/UX Portfolio

A clean, responsive personal portfolio site for Kavinda Weerasekara, Product / UI/UX Designer.
It's plain HTML, CSS and JS, so there's no build step.

## Run locally

Open `index.html` in a browser, or serve the folder:

```bash
python3 -m http.server 8000
# then visit http://localhost:8000
```

## Structure

```
index.html                     # Home page: hero, about, recent work, services, experience, contact
case-studies/                  # Project detail pages, generated by scripts/build_projects.py
assets/css/style.css           # Styles; design tokens (colors, radius, fonts) at the top
assets/js/main.js              # Mobile menu, scroll reveal, copy email
assets/img/kavinda.jpg         # Profile photo
assets/img/favicon.svg         # The "K." mark; favicon-32/192.png and apple-touch-icon.png are PNG versions
assets/img/bee.svg             # The little bee that flies across the hero
assets/img/behance/            # Project covers imported from Behance
assets/data/behance-projects.json        # Projects imported from Behance
assets/data/projects.json      # Content for the project detail pages
assets/docs/Kavinda-Weerasekara-CV.pdf   # Linked from the "Download CV" buttons
scripts/sync_behance.py        # Behance import, run by .github/workflows/behance-sync.yml
```

## Customising

- **Colors and fonts:** edit the variables in `:root` at the top of `style.css` (lime accent, sky-blue gradients, Inter).
- **Recent work:** the `#work` section shows six projects with covers from `assets/img/behance/`.
  To feature a different project, copy a card and use another entry from `assets/data/behance-projects.json`
  (its `cover`, `url`, title and description).

- **Caching:** the pages load `style.css?v=…` and `main.js?v=…`. After changing either file, bump the
  `v=` value in `index.html` and `case-studies/*.html` so browsers fetch the new version straight away.

## Project detail pages

Every Recent work card opens a page in `case-studies/`. The pages share one template in
`scripts/build_projects.py` and take their content from `assets/data/projects.json` (title, facts,
overview, highlights) plus the cover, link and year from the Behance import. After editing either, run:

```bash
python3 scripts/build_projects.py
```

A project can also have a full case study: point its `case_study` field at a JSON file of chapters in
`assets/data/case-studies/` (see `ledgr.json`) and the page renders those chapters, with a sticky chapter
menu, instead of the short overview and highlights.

Chapters can also carry a `board` image (a full case-study board exported from Figma, shown on wide
screens while the text stays available to screen readers) and a `board_ui` crop that phones show
alongside the text. Board images live in `assets/img/case-studies/<project>/` (Ledgr and Lumora so far).

The Recent work cards in `index.html` (between the `rw-cards` markers) are generated from the same file,
including each card's `accent` colour and `card_tags`, so rebuilding also updates the home page.

To add a project, add an entry to `projects.json` with its Behance `behance_id`, rebuild, and add a card
for it in the Recent work section of `index.html`.

## Importing a full Behance project

Behance blocks simple requests, so the **Import a Behance project** workflow (Actions tab → Run workflow, paste
the project URL) opens the page in headless Chrome and commits its text and full-size images to
`assets/data/behance-raw/<id>/`. Use those to write the project's case-study file, then delete the raw images.

## Behance sync

The **Sync Behance projects** GitHub Action reads the public RSS feed of
[behance.net/kavindalakmal](https://www.behance.net/kavindalakmal), downloads each project's cover and updates
`assets/data/behance-projects.json`. It runs daily, or on demand from the repo's **Actions** tab, and
commits any changes. Behance's feed only lists recent projects, so older ones are kept from earlier runs.

## Deploy to GitHub Pages

Repo **Settings → Pages → Build and deployment → Deploy from a branch**, pick the branch and `/ (root)`.
The site will be live at `https://<username>.github.io/<repo>/`.
